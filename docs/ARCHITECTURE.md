# Architecture

One content model, many views. Every tracked thing is a `Chain`; each tab is a
filtered or reshaped view over the single store. Adding a chain or a view never
touches plumbing.

## File map (`web/src/`)

```
content/
  types.ts         The Chain model + Level / DimensionId / Band / Source types.
  methodology.ts   DIMENSIONS, LEVELS, BANDS as data — one definition each,
                   read by the Methodology view AND the rosette labels.
  chains.ts        The store: CHAINS[] (54 chains, seven sourced ratings each) +
                   FEED_META. The only place data is seeded.
  changelog.ts     The public changelog and the list of items under review.
  chainIcons.ts    Monochrome chain marks, generated by tools/gen-icons.mjs.
lib/
  model.ts         The quantitative risk model: factor severities, product/customer
                   weight vectors, resolveWeights(), scoreChain() (contributions,
                   caps, score, grade, drivers), pillars. Unit-tested.
  router.ts        The hash router: parseHash()/formatHash() (pure, unit-tested).
                   Routes: #/ (also #/overview) · #/chains · #/matrix ·
                   #/compare/<ids> · #/method · #/contribute · #/changelog ·
                   #/about · #/chain/<id>, profile as ?p=&c= on any route.
                   RoutePage and PAGES define the pages.
  exportData.ts    Assessment exports: buildAssessment/JSON/CSV (pure, unit-tested)
                   + the downloadFile helper.
  evidence.ts      How much of a grade rests on a cited source, published beside the score.
  sourceOfFunds.ts The factor levels restated as a source-of-funds question (no new data).
  rating.ts        Thin profile-aware wrappers over the model: deriveBand(),
                   concernIndex(), byRisk(profile); plus rosetteWedges() geometry.
  uiTokens.ts      CSS-variable style helpers: RISK_VAR, chipStyle, dotStyle,
                   bandChipStyle, category labels. No enumerated colour classes.
  theme.ts         useTheme() — dark/light via data-theme + localStorage.
  cn.ts            clsx + tailwind-merge helper.
components/
  TopNav.tsx       The slim top nav (tabs, search trigger, theme toggle, LIVE stamp).
  QuickSearch.tsx  The "/" / Ctrl+K quick-open overlay (find a chain, Enter opens).
  Segmentation.tsx The deployment-profile control (product × customer).
  RiskRosette.tsx  The seven-wedge rosette + the radial ConcernGauge + legend.
  ChainGrid.tsx    The all-chain grid, in HTML: tiles grouped by visibility and control,
                   each a button that opens the chain. Replaced the landscape scatter
                   and the beeswarm.
  charts.tsx       Per-chain SVG on a fixed viewBox: ProfileSensitivity (one chain across
                   all products) and ContributionBars.
  primitives.tsx   RiskDot, GradeChip, BandChip, LevelChip, CategoryTag, TierTag, Monogram,
                   Citation, EvidenceChip, sourceHost, Panel, SectionLabel.
views/
  Overview.tsx     The landing page: what it is, a worked example with the rosette, the
                   grade spread and the next steps.
  Ratings.tsx      Segmentation + ChainGrid + ranked grade table + JSON/CSV assessment
                   export. The Ratings tab.
  Matrix.tsx       Chains × seven factors dot grid (L2BEAT-style), grade column. A view
                   mode under the Ratings tab (#/matrix), not a tab of its own.
  Compare.tsx      2–4 chains side by side (grades, rosettes, factors, stats);
                   selection lives in the URL.
  Methodology.tsx  The framework + model explainer (weights table, caps, grades).
  About.tsx        What it is, mission, scope; full-width with a side rail.
  Contribute.tsx   The public submission form, which posts to api/feedback.ts.
  Changelog.tsx    The public record of changes, from content/changelog.ts.
  ChainDetail.tsx  Drill-down: gauge, rosette, the calculation, sensitivity chart,
                   stats, dimensions; print one-pager + per-chain JSON export.
App.tsx            Mirrors the URL hash (the single source of truth) into state;
                   shell + footer.
```

Outside `web/src/`:

- `api/feedback.ts` is the serverless intake for the Contribute form, and `api/_lib/submission.ts`
  holds the types and `formatIssue` that the site shares through the `@shared` alias.
- `web/scripts/` holds the gates (`design-check.mjs`, `prose-check.mjs`, `source-check.mjs`,
  `link-check.mjs`) and `gen-ratings.ts`, which builds `public/ratings.json`.
- `tools/` holds `inbox.mjs` (the submission queue) and `gen-icons.mjs` (the chain marks).

## State

**The URL hash is the single source of truth.** `App.tsx` parses it into a
`Route` (page, open chain, compare ids, deployment profile) via `lib/router.ts`,
mirrors it in React state, and listens to `hashchange`. Navigation assigns
`location.hash` (a history push, so back works); profile changes use
`history.replaceState` (a dropdown tweak should not bury the back button). Every
state is therefore a shareable link, e.g. `#/chain/tron?p=payments&c=retail`.

## Adding a chain

Append one object to `CHAINS` in `content/chains.ts` with the seven ratings
(`level` + `rationale` + `sources`), plus the required `exposure` and `residual` fields. The band, concern index, rosette and every
view update automatically. No component changes.

## Adding a view

Add a `RoutePage` value and extend the `PAGES` array in `lib/router.ts`, add an entry to `TABS` in
`TopNav.tsx` if it is to be a tab, and add a branch in `App.tsx` that
renders a new component under `views/`. The view reads `CHAINS` and reuses the
primitives. Keep it a thin projection of the store.
